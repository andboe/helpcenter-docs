== WFM settings overview page

=== General

[%header, cols="1a,1a,".rstrip(',')]
|===
|Name
|Description
|[48121] Earliest start time for night work
|Specifies the earliest possible start time for night shifts, measured in seconds from midnight. For example, 3600 corresponds to 1:00 AM and 79200 to 10:00 PM. The default value is 0.
|[48122] Night work duration
|Specifies the latest possible end time for night shifts, measured in seconds from the start time value specified in WFM setting 48121. For example, a value of 36000 and a start time of 10:00 PM yields a latest possible end time for night shifts of 08:00 AM.
|[48161] Mode for defining night work
|Defines what constitutes a night shift. If set to 0, a shift is a night shift if it lies entirely within the time range specified by the WFM settings [48121] Earliest start time for night work and [48122] Night work duration. If set to 1, a shift is a night shift if it includes the reference time defined in WFM setting [48162] Reference time for night shifts.
|[48162] Reference time for night shifts
|Defines the reference time used to identify night shifts when mode 1 is selected in WFM setting 48161. The value represents a time of day, expressed in seconds since midnight (e.g. 79200 for 10 PM). Shifts or activities that begin, end, or overlap with this reference time are classified as night shifts.

=== SchedulePro

==== General

[%header, cols="1a,1a,".rstrip(',')]
|===
|Name
|Description
|[48184] Take into account the hierarchy of the planning units
|Specifies whether the planning unit hierarchy should be considered when scheduling and calculating target work and time accounts. When enabled with value 1, child planning units inherit planning periods from their parent, and these are used in calculations without needing to create new planning periods. The inherited periods are also visible in the Planning Periods menu of SchedulePro. When disabled with value 0, only the directly assigned planning unit is considered. The default value is 0. Planning periods are called scheduling periods in Peopleware.

==== Shift Center

[%header, cols="1a,1a,".rstrip(',')]

|Description

|Defines when the hour scale display begins in the Shift Center view. Controls the visual starting point of the scheduling timeline for users. Enter time in seconds from midnight. The default value is 0.

Available options: +- 0 = Display the first scheduled activity or shift (default) +- 1 = Display the last scheduled activity or shift +- 2 = Display the day status; if no day status is available, show the first activity or shift +- 3 = Display the day status; if no day status is available, show the last activity or shift

|Controls whether Shift Center saves the user's display preferences. If enabled (value '1'), the layout and view settings will be restored the next time the user opens the Shift Center. If disabled (value '0', which is the default), no preferences are retained.

=== Optimization

[%header, cols="1a,1a,".rstrip(',')]
|===
|Name
|Description
|[48069] Take suitability percentage into account
|Determines how skill levels suitability percentages affect coverage and scheduling. 0 ignores skill levels; all people are treated as 100% suitable. 1 uses skill percentages for coverage (e.g., 50% skill = 0.5 coverage), but not for scheduling order. 2 uses skill percentages for both coverage and scheduling priority. People with higher skill levels are scheduled first when possible. The default value is 0.
|[48591] Start time for re-optimization period
|Defines when re-optimization begins for the current day. Applies to Break Optimization, Job Optimization, and AutoScheduler. The time must be entered in seconds since midnight UTC and converted to the planning unit’s time zone. Only shifts, activities, and breaks fully within the re-optimization window are affected. For Break/Job Optimization, the window ends at the time set in [48592]. For AutoScheduler, it ends at the end of the optimization period and requires the "Optimize Again" option to be active. Enter 0 to disable re-optimization and use the full period instead. Default is 0. Example: If the planning unit is in UTC+1 and you want the re-optimization period to start at 06:00 local time, first convert 06:00 to UTC, which is 05:00. Then calculate the seconds since midnight UTC:
|5 × 3600 = 18 000.
|[48592] End time for re-optimization period
|Defines the end time for the re-optimization period of the current day. This setting applies to Break Optimization and Job Optimization, and only if [48591] is set to a value greater than 0. The value must be entered in seconds and represents how much time should be subtracted from the end of the planning unit’s business hours to determine the re-optimization end time. A value of 0 means optimization continues until the end of the business day. This setting is relative to local business hours and does not require time zone conversion. AutoScheduler ignores this setting and always uses its full optimization period.
|===

|Description

|Defines the smallest time block in seconds for splitting the default activity Present during Job Optimization. Each segment can be assigned a different activity. ==== AutoScheduler

[%header, cols="1a,1a,".rstrip(',')]
|===
|Name
|Description
|[48303] Minimum duration of activity segments when splitting shifts compatible with multiple activities
|Defines the smallest segment size, in seconds, used to split the default activity Present during schedule optimization. Each segment can receive a different required activity. Enter a value between 900 and 86400 seconds. Peopleware rounds it down to the nearest multiple of 900. Enter 0 to disable segmentation. Schedule optimization supports up to 64 segments per day. Using small values may slow performance, especially with long shifts or if WFM setting 48069 is enabled. To merge identical adjacent segments, activate WFM setting 48304.
|[48309] Take into account existing activities
|Controls how AutoScheduler handles activities already scheduled in the Shift Center. +- 0: Default value. Keep all existing activities. AutoScheduler can still replace activities with ID 1. It schedules shifts around fixed items such as meetings. You can change day models before scheduling begins. +- 1: Add or adjust activities only when needed to reach each person’s contractual working hours. For example, if a person has a 40-hour contract but only 35 hours scheduled, AutoScheduler adds activities until the contract is met. It can replace ID 1 activities. It places shifts before or after meetings and ensures breaks do not overlap with them. You can change day models before scheduling begins, but not during. +- 2: Add or adjust activities as needed to meet staffing requirements, even if people end up working more or fewer hours than their contracts specify. AutoScheduler can replace activities with ID 1. It places shifts before or after meetings and ensures breaks do not overlap with them. You can change day models at any time during scheduling. This mode requires more system resources.
|[48408] Take into account business hours in AutoScheduler
|Controls how schedule optimization interprets a planning unit’s business hours. +- 0: Check only whether the planning unit has business hours on the day. If business hours exist, schedule optimization runs normally. If not, schedule optimization ignores staff requirements for that day. +- 1: Use the exact start and end times of business hours. Schedule optimization places people only within that time window. +- 2: Apply business hours as a hard limit. Schedule optimization places people only if the full staff requirement fits within the business hours. +- 3: Restrict scheduling to the time ranges when the planning unit assigns the required activity. Schedule optimization places people only in those relevant time slots.
|===

|Description

|Defines how many days from the current day are locked for shift swap to protect the current schedule. During this period, shift swap is disabled. The default value is 3.

|Specifies whether shift swaps require planner approval. Enter 0 to require approval. Enter 1 to allow people to swap shifts without approval.

|Specifies whether people can exchange entire work days across different dates. |[48999] Enable specific checks for subactivities of multi-activities in association with scheduling rule 2605
|Enables checks for subactivities when people exchange multi-activities, based on rule 2605. Enter 1 to allow exchanges only if both persons have identical subactivity sets. Enter 0 to disable the check. The default value is 0.

=== Time Management

[%header, cols="1a,1a,".rstrip(',')]
|===
|Name
|Description
|[48473] Source level for scheduled data
|Defines which scheduling level is used as the source of scheduled data in Time Management calculations. The Rules functionality in Time Management compares this scheduled data with the actual hours data as specified in WFM setting 48474. 1000 sets the level to Schedule. 3000 sets the level to Actual. 8000 sets the level to Version 1. This setting also determines which level is used to display account balances in Shift Center.
|[48474] Source level for Actual Hours data
|Defines which scheduling level is used as the source of actual hours or actual data in Time Management calculations. The Rules functionality in Time Management compares this actual data with the scheduled data as specified in WFM setting 48473. 1000 sets the level to Schedule. 3000 sets the level to Actual. 4000 sets the level to Time Recording. 4001 sets the level Correction. 5000 sets the level to External System.
|[48475] Source Level for Reference Data
|Legacy setting. This setting is no longer supported.
|[48518] Show/hide the Account Balances editing category in the TimeKeeper module
|Legacy setting. This setting is no longer supported.
|[48544] Inspection period for punches
|Controls how the inspection period is defined in Payroll Control. Value 0 uses the standard month and year selection. Value 1 enables manual date entry using From and To fields instead.
|[48597] Month for the border day
|Works in combination with setting [48596] to define the border day used in the Special-Day Payout menu. The border day is used for tax-related assessment and is calculated based on a specific day and a number of months after the special day. Defines how many months after the special day the border day occurs. Accepted values: 0 to 11 (default is 1, meaning the following month).
|[48598] Account for the credit factor
|Specifies the account used to calculate additional credit for special days. The calculation factor is defined per special day through time management rules. Enter the ID of an existing account. If no account is specified, no credit is posted, and Peopleware defaults to a factor value of 1. There is no default account.
|[48599] Account for 'Compensatory Time Off'
|Specifies which account is used to display values in the Compensatory Time Off column. This account holds working time eligible for additional credit as time off. For example, if an employee receives 50% additional credit for 4 hours worked, they are credited with 6 hours total. The credited time contributes to the employee's compensatory time entitlement. Enter the ID of an account. No default account is set.
|[48600] Account for 'Hours Worked'
|Specifies which account supplies the data shown in the Hours Worked column for special days. This account includes both standard working hours and any hours eligible for additional credit on a special day. Enter the ID of an account. No default account is set.
|[48601] Account for 'Payable Hours'
|Defines the account used to populate the Hours Worked column for special days. This account should contain both regular working hours and any hours eligible for additional credit on those days. Enter the ID of an account. No default account is specified.
|[48604] Refresh period for Special Days
|Defines how frequently Peopleware refreshes the date, in milliseconds. Accepted range: 0 to 60000. The default value is 2000 (i.e. every 2 seconds). Enter 0 to disable automatic updates.
|[48615] Code for punches made using the time recording system
|Defines a code used to label punches recorded via the time recording system. This code appears in the Payroll Adjustment and Closing Operations menus. Enter a single letter (A–Z). There is no default code.
|[48616] Code for automatically generated punches
|Defines a code used to label automatically created punches that replace missing ones (e.g., when a person forgets to clock out). This code appears in the Payroll Adjustment and Closing Operations menus. Enter a single letter (A–Z). The default value is 'a'.
|[48617] Code for manually adjusted punches
|Specifies the code used to label punches that are manually adjusted in the Payroll Adjustment menu. The code is also displayed in the Closing Operations menu. Enter a single letter (A–Z). The default value is 'k'.
|[48619] Signal activity for punches deleted from the 48620 Storage level for corrections
|Defines an internal activity to be stored at the correction level defined in WFM setting 48620 when all punches are deleted. This signal activity is automatically inserted to indicate the absence of punches. If no activity is set here and the correction level is empty, the system displays data from the actual hours source level defined in WFM setting 48474 instead. Enter the ID of the signal activity. No default is set. The user interface does not display the signal activity.
|[48622] Source level for displaying scheduled day models or activities
|Specifies which data level is used to display day models or activities in the Scheduling Data column of the Payroll Overview menu and report. The selected level must contain the assigned day model or activities for the employee on the given day. Possible values: + 1000 = Schedule (default) +- 2000 = Request +- 2001 = Alternative Request +- 2002 = Vacation/Absence Request +- 3000 = Actual +- 4000 = Time Recording +- 4001 = Correction +- 5000 = External System +- 6000 = Availability +- 6001 = On Call +- 8000 = Version 1 +- 8001 = Version 2 +- 8002 = Version 3 +- 9000 = Personal Limits to Work Time Adjustment.
|[48635] Code for automatic punches that have been deleted
|Defines a code used to label automatic punches that have been manually deleted by a planner. This code appears in the Payroll Adjustment and Closing Operations menus. Enter a single letter (A–Z). The default value is 'a'.
|[48667] Payment Type in report Payroll Overview for employees
|Controls whether Payment Type information is included in the Payroll Overview report when accessed by employees through Reports or {bc-me-calendar}. Value 1 displays Payment Type information. Value 0 hides it. The default value is 0.
|[48668] Time accounts in report Payroll Overview for employees
|Defines which time accounts should appear in the Payroll Overview when generated by employees via either the Reports module or {bc-me-calendar}. Attributes and Time accounts must be assigned to people. Enter the ID of the attribute you want to use. There is no default value.
|[48691] Activity for 'Scheduling Data'
|Consolidates consecutive scheduled activities into a single entry. Applies to both the Payroll Overview and Payroll Adjustment menu items. To group activities, enter the ID of the activity you want to display (e.g., enter '1' to show 'Present'). To display each activity separately, enter 0. The default value is 1.
|[48692] Displaying scheduled breaks after dissociating a day model from the shift concept
|Hides or displays breaks once the day model has been dissociated from the shift concept on a given day. Applies to the Payroll Overview and Payroll Adjustment menu items. Value 1 displays breaks, value 0 hides them. The default value is 1.
|[48693] Storing and recalculating manual changes
|Determines how the Rules feature handles recalculations when manual changes are made in Time Management. Applies to Punches and Time Categories. Value 0 always retains the initial statuses of punches and time categories. Value 1 recalculates the statuses, including the "No Break Taken" column in Payroll Adjustment, only for the most recently adjusted punches and time categories if they differ from the originally calculated values. Value 2 recalculates punches only on dates where no manual changes have been made. Time Categories are recalculated as in option 1, regardless of any changes to punches. Value 3 always retains manually adjusted punches and time categories without recalculation.
|===
