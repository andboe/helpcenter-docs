This article explains how to create a CSV schema.

[#prerequisites]
== Prerequisities
- You have the **Configure CSV schemas** permission.
- You have a CSV sample file that is representative of the CSV files that will be imported with the CSV schema. The CSV sample file includes all the columns and header rows and at least one data row.

[#steps]
== Steps
Creating a ready-to-use CSV schema is a two-step process.
First, you create a CSV schema draft and specify general and file processing settings based on the sample file.
Then you map the columns available in the sample file to the target fields Peopleware expects for the schema type.

The CSV schema will only be available for manual CSV imports and CSV integrations when the mapping is complete.

[#create-csv-schema-draft]
=== Create CSV schema draft
1. Go to menu:Account[CSV Schemas]
2. Click btn:[Create].
3. Configure general and file processing settings as needed.
4. Upload the CSV sample file.
5. Click btn:[Save]

Peopleware saves the CSV schema draft and opens the details page.

[#map-columns]
=== Map columns
The schema type controls which columns need to be mapped to target fields in Peopleware.
Usually, mapping is required for date and time values and for data specific to the object type, e.g. forecasts.

1. On the details page of the CSV schema draft, go to the **Date and time columns** section.
2. If the CSV sample file stores date and time data in a single column, activate the **Date and time in one column** setting.
3. For every date or time field, assign the corresponding CSV column and specify the value format.
4. Go to the **Data column mapping and processing** section.
5. Assign the target fields to their corresponding CSV column.
6. Click btn:[Save]

Depending on the schema type, the CSV schema can now be used to import CSV data via the CSV import dialogs or a CSV integration.

[#schema-subtypes]
==== Schema subtypes for contact data
CSV schemas with schema type **Contact data** must specify a schema subtype.
Schema subtypes are either interval-based or contact-based:

- **Interval based**: The CSV schema expects all contact data to be provided in aggregated form on one line per interval.
- **Contact based**: The CSV schema expects all data to be provided on one line per contact.

Additionally, schema subtypes control how the data provided in the CSV files needs to be mapped:

- **SQL**: The CSV schema maps CSV file columns to Peopleware target fields via an SQL query. Select this option if one of the following applies:
  - At least one of the required Peopleware target fields is not available as a column in the CSV import file.
  - The CSV import file includes values in an unsupported format that needs to be converted to a supported format.
  - You want to perform calculations on the data provided in the CSV import file and save the results in a target field.
- **column mappings**: The CSV schema maps CSV file columns directly to target fields in Peopleware.

For information on how to perform SQL mapping, see section xref:#sql-mapping[Use SQL to map contact data].

[#sql-mapping]
== Special use case: Use SQL queries to map contact data
The schema type **Contact data** supports mapping using SQL queries.
Consider SQL mapping in the following cases:

- The CSV import files do not provide the required data in a dedicted column.
- Column values are in an unsupported format that may require data conversions or calculations.

SQL mapping allows you to add default values for missing columns, convert data using SQLite functions, or run calculations.

[NOTE]
====
====
>
[NOTE]
====
See [sqlite.org](https://www.sqlite.org) for details and limitations on functions and conversions:
====
>
[NOTE]
====
- [numeric precision](https://www.sqlite.org/datatype3.html)
- [math functions](https://www.sqlite.org/lang_mathfunc.html)
- [implicit data conversions](https://www.sqlite.org/datatype3.html#affinity)
- [date and time functions](https://www.sqlite.org/lang_datefunc.html)
- [string manipulation](https://www.sqlite.org/lang_corefunc.html#string_functions)
====
To use SQL mapping instead of mapping target fields directly, select the **Contact data** schema type and then one of the following schema subtypes:

- **Interval based - SQL**
- **Contact based - SQL**

For these schema subtypes, Peopleware displays an SQL query field in the **Data column mapping and processing** section instead mapping target fields.

[#basic-query]
=== Basic query
As a starting point, use the following basic example queries that show the required columns and table name:

- Interval-based contact data:

[source,sql]
----
SELECT
queue, timestamp,
offered, handled, aht,
channel
FROM uploaded_file
----

- Contact-based contact data:

[source,sql]
----
SELECT
queue, timestamp,
offered, handled, duration,
channel
FROM uploaded_file
----

[#advanced-query-examples]
=== Advanced query examples
The following advanced query examples show how to apply mathematical operations and SQLite functions.

Note the following requirements:

- Use `uploaded_file` as table name.
- Use lowercase column names (also if you refer to different column names in column aliases), e.g. `QueueNameColumn as queue`.
- Use a date formatted as `YYYY-MM-DD hh:mm:ss` or convert your date to this format. <!-- before it said, datetime required. This is not true for CSV but only for database integrations -->

SELECT
  Queue as queue,

[#example-2-column-names-with-blank-characters]
==== Example 2 (column names with blank characters)
- Use SQLite's `date('now')` to get the current date and combine this with the time from the file.
- Strip decimals and convert them to integers.
- Combine Date and Time using SUBSTR for the required YYYY-MM-DD HH:MM:SS timestamp format.

You can refer to the actual column names using double quotes:

[source,sql]
----
 SELECT
   "Queue Name" as queue,
   DATE('now')||' '|| "Hour in hh:mm"||':00' as timestamp,
   FLOOR("Offered Calls") as offered,
   FLOOR ("Handled Calls") as handled,
   (CAST(substr("Average Handling Time", 1, 1) AS INTEGER) * 3600) +
   (CAST(substr("Average Handling Time", 3, 2) AS INTEGER) * 60) +
   CAST(substr("Average Handling Time", 6, 2) AS INTEGER) as aht,
   'calls' as channel
FROM uploaded_file
----

Alternatively, you can replace the header row by using the following file processing options:

- **Skip first x rows**: Enter `1`to remove the original header.
- **File has no header row**: Check to add column headers with letters

[source,sql]
----
 SELECT
   A as queue,
   DATE('now')||' '|| B || ':00' as timestamp,
   FLOOR(C) as offered,
   FLOOR (D) as handled,
   (CAST(substr(E, 1, 1) AS INTEGER) * 3600) +
   (CAST(substr(E, 3, 2) AS INTEGER) * 60) +
   CAST(substr(E, 6, 2) AS INTEGER) as aht,
   'calls' as channel
FROM uploaded_file
----

[#example-4-case-statement-for-contact-based-data-and-iso8601-date-conversion]
==== Example 4 (CASE statement for contact-based data and ISO8601 date conversion)
Contact-based data records often do not have a column with the number of offered and handled calls. Instead, you will see boolean values for the type of contact:

[%header, cols="1a,1a,1a,1a,1a,".rstrip(',')]
|===
|Queue
|DateTimeISO8601
|Offered
|Answered
|Duration
|My Inbound Queue
|2023-01-01T22:59:00
|true
|true
|100
|My Inbound Queue
|2023-01-01T23:59:00
|true
|false
|100
|===

- Use a CASE statement for contact-based data with boolean values for offered and handled calls.
- Transform an ISO8601 formatted date into the required YYYY-MM-DD HH:MM:SS format.

[source,sql]
----
SELECT
   "Queue" as queue,
   substr("DateTimeISO8601", 1, 10) || ' ' || substr("DateTimeISO8601", 12, 8) as timestamp,
   (CASE WHEN "Offered" = 'true' THEN 1 ELSE 0 END) as offered,
   (CASE WHEN "Answered" = 'true' THEN 1 ELSE 0 END) as handled,
   "Duration" as duration,
   'calls' as channel
FROM uploaded_file
----

This query will also work for real ISO8601 timestamps, such as data in UTC (2023-01-01T22:59:00Z) or timestamps with the offset of your time zone (2023-01-01T22:59:00+02:00)
