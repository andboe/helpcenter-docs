Use this calculation for asynchronous work, like emails or tickets, that needs to be handled within a predefined time frame. The script calculates staff requirements by spreading the workload evenly across the selected days and hours.

[#calls-outbound]
=== Calls - Outbound
Use this calculation for outbound campaigns where the workload is based on the number of records to dial. This option factors in contact rates, redials, right-party connect rates, and handling times to calculate staff requirements over the campaign period.

**Campaign data**

[%header, cols="1a,1a,".rstrip(',')]
|===
|Parameter
|Description
|Queue
|The source forecast queue used as basis for the calculation.
|Version
|The forecast version used as basis for the calculation.
|Records
|Number of contacts to call. +- Fixed: Uses a fixed number of records. +- Variable: Uses a queue as the data source.
|Contact rate (%)
|Expected percentage of contacts where a contact attempt is successful.
|Redial rate (%)
|Percentage of contacts that require a redial attempt.
|Start date
|The start date from which the calculation applies.
|End date
|The end date until which the calculation applies. +- Date: Uses a fixed end date. The campaign stops exactly on that date +- Campaign duration in days. Peopleware calculates the end date automatically by adding those days to the start date.
|Right party connect rate (%)
|Percentage of contacts where the correct person is reached. +- Fixed: Uses a fixed number of records. +- Variable: Uses a queue as the data source.
|Shrinkage (%)
|Percentage of paid time where people are unproductive, e.g. break, sickness.

[#distribution-contacts-time-frames]
=== Distribution - Contacts (time frames)
Use this calculation to distribute inbound contacts from a source queue across multiple target queues, representing service providers, or internal teams. The allocation is based on specific percentage distribution values that you can define for each day and time span. Once configured, the calculation adds formulas to the value type to display the results of the distributed contacts.

**Calculation parameters**

[%header, cols="1a,1a,".rstrip(',')]
|===
|Parameter
|Description
|Start date
|The start date from which the distribution applies.
|Number of days with timespans
|The number of days from the start date for which you can enter staff requirements.
|Number of days
|Total length of the distribution period.
|Timespans per day
|The number of time periods per day for which you can enter staff requirements.
|Consider each day of the week
|- Yes: Staff requirements are calculated for the selected weekdays until the end of the date range. +- No: Staff requirements are calculated repeatedly, starting with day 1 and regardless of the weekday, until the end of the date range.
|Number of service prodivers
|Number of “targets” to which contacts are distributed.
|Version
|The forecast version used as basis for the calculation.
|===

**Source parameters**

[%header, cols="1a,1a,".rstrip(',')]
|===
|Parameter
|Description
|Queue
|The source forecast queue used as basis for the calculation.
|Value type (contacts)
|The value type from the source queue.
|===

**Target parameters**

[%header, cols="1a,1a,".rstrip(',')]
|===
|Parameter
|Description
|Value type (percentages)
|Percentage distribution across service providers.
|Value type (calculated contacts)
|The resulting number of contacts per target.
|===

**Percentage distribution**

[%header, cols="1a,1a,".rstrip(',')]
|===
|Parameter
|Description
|Service provider
|The target queues for the calculation.
|Time difference to source queue
|Optional. Shifts contacts in time relative to the source queue.
|Day
|Weekday for which the distribution applies.
|Start/end
|Defines the exact time frame within the day.
|Percent per provider
|The share of contacts allocated to each service provider in that time frame. Must add up to 100% across providers.
|===
