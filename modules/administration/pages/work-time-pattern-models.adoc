= Create work time pattern models

:author:

:product-label: advanced, enterprise
:topic-type-concept:
:description: Use work time pattern models in your schedule optimization to ensure that employees are not simply given random shifts.
:related-articles: scheduling-optimization.adoc, employee-overview.adoc, create-contracts.adoc, daymodel-creation.adoc, scheduling-split-shifts.adoc
:page-aliases: wtpm_creating

A work time pattern model is made up of xref:#create-week-time-patterns[week time patterns] and defines how xref:administration:daymodel-basics.adoc[day models] are assigned to your people.

The following image shows the setup of day models and week time patterns in a work time pattern model.

image::work-time-pattern-models/image-1.png[Structure of a work time pattern model]

With work time pattern models you can create repeating patterns of shifts, and set scheduling constraints for the *Create optimized schedule* functionality. +
Work time pattern models have the following benefits:

- They define which day models can be used to plan a person.
- People are not assigned shifts in random combinations.
- They define starting times for shifts.
- They define an order for the assignment of day models.

As an alternative to work time pattern models, you can use shift sequences or configure xref:administration:availabilities.adoc[availabilities] for your people.

[#prerequisites]
== Prerequisites
To be able to use work time pattern models, make sure the following applies:

- You have created xref:administration:daymodel-creation.adoc[day models] and xref:#create-week-time-patterns[week time patterns], and assigned day models to the week time patterns.
- Each work time pattern model contains at least one week time pattern.
- Each week time pattern contains at least one xref:administration:daymodel-basics.adoc[day model].
- You have assigned work time pattern models to your people.

[#create-week-time-patterns]
== Create week time patterns
A week time pattern is a group of day models. You can group day models by any criteria, e.g. shift length, activities involved, starting time, etc. +
You can only use week time patterns as part of a work time pattern model. For a working week, people are scheduled according to the day models included in the week time pattern. This way, you can ensure that your people have fairer and more consistent working hours.

To create a week time pattern, follow these steps:

1. Go to menu:Plan[Configuration>Week time patterns].
2. {btn-create}
3. Configure the settings of the week time pattern:
   - *Name*: Enter a unique name (max. 50 characters).
   - *Abbreviation*: Enter the name or a shorter version of it (max. 25 characters).
   - *Maximum number of exception days per week*: xref:#exception-days[Exception days] allow to break the rules of the work time pattern model to better meet staff requirements.
4. {btn-create}

You can now add day models to your week time pattern.

[#add-day-models-to-a-week-time-pattern]
=== Add day models to a week time pattern
1. In the configuration window of the week time pattern, go to the *Day models* section and click {icon-edit} Edit.
2. Select one or more day models from the list.
3. {btn-save}

You can add both xref:administration:daymodel-basics.adoc#types-of-day-models[fixed and variable day models] to a week time pattern. If you use variable day models, the *Create optimized schedule* functionality can determine the optimal starting time of the shifts within the constraints set by the day model.

[NOTE]
====
Only day models assigned to the planning unit added to the person can be scheduled. If you have xref:administration:create-and-manage-planning-units.adoc#limit-day-models[limited the day models] in your planning unit, the day models you expect based on your work time pattern model may not be used.
====
>
[NOTE]
====
Replaceable activities can be replaced with plannable activities within a shift. For this to work, use variable day models for each shift duration a contract requires, and use the system activity Present (ID: 1) as xref:administration:daymodel-basics.adoc#base-activity-and-shift-duration[base activity]. Do not define day models for each individual activity.
====
[#create-work-time-pattern-models]
== Create work time pattern models
1. Go to menu:Plan[Configuration>Work time pattern models].
2. {btn-create}
3. Configure the settings of the work time pattern model:
   - *Name*: Enter a unique name (max. 50 characters).
   - *Abbreviation*: Enter the name or a shorter version of it (max. 25 characters).
   - *Type*: The xref:#types-of-work-time-pattern-models[type] determines how the work time pattern model is used.
   - *Week Time Pattern - Exception Days*: Select the week time pattern that should be planned for xref:#exception-days[exception days].
   - (Optional) *Description*

4. {btn-save}

You can now add week time patterns to your work time pattern model.

[#add-week-time-patterns-to-a-work-time-pattern-model]
=== Add week time patterns to a work time pattern model
1. In the configuration dialog of the work time pattern model, click *+ Add* in the *Week time patterns* section.
2. Choose a *Week time pattern* from the list.
3. Set a *Position*.
   If you add several week time patterns, click the {icon-down-arrow-blue} and the {icon-up-arrow-blue} to change the position.
4. {btn-ok}

[#position]
=== Position
The position of week time patterns within work time pattern models is relevant when you use work time pattern models of xref:#types-of-work-time-pattern-models[type B or D]. The week time patterns are assigned in the order configured here.

[#types-of-work-time-pattern-models]
== Types of work time pattern models
[%header, cols="1a,1a,1a,1a,1a,".rstrip(',')]
|===
|Type
|Week time pattern use
|Day model assignment
|Shift start time
|Effect
|Flexible
|Peopleware can select any day model from any of the week time patterns included for every day of every week.
|Peopleware can use any day model from any of the week time patterns.
|Flexible
|Depending on your organization’s opening hours, this type can result in a shift distribution that seems random or stressful to your people. For example, a person could have to work early on Monday, at night on Tuesday, and late on Wednesday, etc.
|Fixed
|Peopleware plans the week time patterns in the order defined by their positions.
|Peopleware chooses one day model for the whole week.
|Fixed
|Each person is assigned the same day model for the entire week, e.g. starting at 9 AM from Monday to Friday. Define xref:#exception-days[exception days] if you want to plan a different day model. Fixed Rotation is the most consistent shift assignment of all four types.
|Variable
|Peopleware does not respect the defined position of week time patterns.
|Peopleware chooses one day model for the whole week.
|Fixed
|People can be assigned any week time pattern to best meet staff requirements. Since the shifts start at the same time, people have consistent working hours throughout the week.
|Combined
|Peopleware respects the position defined for the week time patterns.
|For each week, Peopleware chooses the day model that best meets the staffing needs.
|Flexible (within a time frame)
|Based on staff requirements, Peopleware can schedule people with early shifts to start working between 8 AM and 10 AM. With this type, Peopleware can schedule more flexibly to best meet staff requirements, while at the same time assigning fairly consistent schedules to your people.
|===

[#exception-days]
== Exception days
Exception days allow to break the rules defined by the xref:#types-of-work-time-pattern-models[work time pattern model type] in use. For example, you could use exception days to plan one night shift in a week in which the person usually works the morning shift. +
Exception days prioritize staff requirements and ensure better coverage. However, they result in less consistent schedules for your people.

To plan exception days, follow these steps:

1. xref:#create-week-time-patterns[Create a separate week time pattern] and add to it the day models you want to use as exceptions.
2. In the configuration dialog of the week time patterns that you want to use for the standard shift, define the number of exceptions days per week.
3. In the configuration dialog of the work time pattern model, select the week time pattern you want to use for exception days.

When choosing a day model for the week, Peopleware cannot use day models defined for exception days. Make sure that all configuration data required for scheduling (i.e. all day models used, as well as the work time pattern model) complies with the xref:administration:create-contracts.adoc#work-time-guidelines[work time guidelines] defined in the person's contract. If the day model used for the week matches the contract, the original day model can be replaced with one defined for exception days, to better meet staff requirements.

[#add-work-time-pattern-models-to-people]
== Add work time pattern models to people
1. {nav-to-people}
2. {select-person}
3. In the left-side menu, click *Planning*.
4. In the *Work time pattern models* section, click {icon-plus} *Add*
5. {configure-info}
   - *Work time pattern model*
   - *Reference date*
   - *Valid from* and *Valid to*: Configure these dates if you want to add the work time pattern model only temporarily to the person.

6. {btn-save}

Use the xref:people:concept-mass-update.adoc[mass update functionality in WFM] to assign a work time pattern model to several people at once.

[NOTE]
====
Caution when using mass update to assign work time pattern models of type B
====
>
[NOTE]
====
If you use the mass update functionality and set the same reference date for everyone, all people will be scheduled with the same week time pattern at the same time.
====
>
[NOTE]
====
Instead, select smaller groups for the mass update, and set subsequent Mondays as reference dates for them. This way, each group will start their rotation in a different week.
====

[#examples]
== Examples
[#example-a-fixed-rotation-with-early-and-late-shifts]
=== Example A: Fixed rotation with early and late shifts
Configure a work time pattern model of type B (fixed rotation), and assign three different week time patterns to it. Remember to define the position for the week time patterns.

- Week time pattern 1 (position 1) contains day models for morning shifts (shifts start between 7 AM and 9 AM).
- Week time pattern 2 (position 2) contains day models for evening shifts (shifts end at 11 PM).
- Week time pattern 3 (position 3) contains day models for afternoon shifts (shifts start between 11 AM and noon).

With this work time pattern model, people will rotate consistently between one week with morning shifts, one week with evening shifts, and one week with afternoon shifts.

While this requires certain flexibility, people have very consistent working hours throughout the week.

[#example-b-exception-days-for-night-shifts]
=== Example B: Exception days for night shifts
Configure a work time pattern model with three different week time patterns. Configure a maximum of two exception days per week.

- Week time pattern 1 contains day models for morning shifts.
- Week time pattern 2 contains day models for evening shifts.
- Week time pattern 3 contains day models for night shifts (select this one in the drop-down menu *Week Time Pattern - Exception Days*).

With this work time pattern model, people will alternate between morning shifts in the first week and evening shifts in the following week. However, because you have defined two exception days, people can also be assigned two night shifts per week, if this is the best assignment to meet staff requirements.
